# StormHacks Reading Companion

## Overview

LOOB is a reading companion that helps a reader engage with a short passage through typed or spoken questions. It can answer questions using the displayed passage, transcribe microphone input, and narrate passages or answers.

## Architecture

- `src/` — Next.js 16 / React 19 browser application.
- `src/components/ReadingDesk.tsx` — the reading interface, question chat, microphone recording, and playback controls.
- `src/lib/api.ts` — client for the local API service.
- `backend/` — FastAPI service that protects provider credentials and exposes the API.
- `backend/app/main.py` — `/health`, `/v1/ask`, `/v1/transcribe`, and `/v1/speech` endpoints.

## Services

- OpenAI Responses API answers questions about the current page.
- ElevenLabs Speech-to-Text converts a recorded question to text.
- ElevenLabs Text-to-Speech narrates passage text and assistant answers.

The browser talks only to the local FastAPI service. Provider keys belong in `backend/.env` and must never be committed.

## Local development

1. In `backend`, create and activate a Python virtual environment, then run `pip install -r requirements.txt`.
2. Create `backend/.env` with `OPENAI_API_KEY`, `ELEVENLAB_API`, and `ELEVENLAB_VOICE_ID`. Optional settings include `OPENAI_MODEL`, `ELEVENLAB_STT_MODEL`, `ELEVENLAB_TTS_MODEL`, and `ALLOWED_ORIGIN`.
3. Start the API with `uvicorn app.main:app --reload --port 8001`.
4. From the repository root, run `npm install` and `npm run dev`.
5. Open `http://localhost:3000` and allow microphone access to try voice questions.

The frontend defaults to `http://127.0.0.1:8001`; override it with `NEXT_PUBLIC_API_BASE_URL` when needed.

## OCR improvement plan

### Current state and likely cause

The camera OCR prototype lives in `backend/computer vision/book_ocr.py`. It takes one camera frame, applies a fixed 8–92% page crop, enlarges and thresholds it, then calls Tesseract with one page-segmentation mode (`--psm 4`). Its cleanup runs only after OCR and admits any line with at least 35% letters or digits. As a result, decorative artwork, page borders, textures, and layout fragments can be emitted as apparent text before the code has a chance to reject them.

`backend/requirements.txt` does not currently declare the prototype's `opencv-python`, `numpy`, or `pytesseract` dependencies. Add them when the OCR prototype becomes part of the supported setup.

### Goal

Extract readable book text while rejecting non-text regions. The system should prefer a clear “page needs recapture” result to confidently saving gibberish or illustration patterns as a page.

### Implementation phases

1. **Create a repeatable benchmark first.** Capture and retain a small, permission-safe local set of representative frames: clean text, curved pages, shadowed pages, glossy/glare pages, illustrations, chapter decorations, and pages with mixed text and images. Store the expected text or a “reject / no readable text” label beside each image. Record baseline character/word error rate, accepted non-text frames, latency, and Tesseract confidence.
2. **Capture the best source frame.** After a page flip, sample several frames rather than accepting the last one. Score sharpness with variance of the Laplacian, reject frames that are overly dark or clipped, and use the sharpest stable frame. Expose camera index, capture delay, and a saved diagnostic frame for calibration.
3. **Locate and straighten the page.** Replace the fixed percentage crop with a document-contour detector plus a manual fallback crop. Order the four page corners, correct perspective with a homography, detect orientation, and deskew the resulting page. This keeps text baselines horizontal and removes much of the surrounding book stand and background.
4. **Use text-aware preprocessing.** Generate a small set of candidate images rather than one universal threshold: grayscale + contrast normalization (CLAHE), adaptive thresholding, and an illumination-corrected variant for shadows/glare. Use light morphology only when it improves the benchmark; aggressive opening can erase punctuation and thin strokes.
5. **Choose OCR based on confidence and layout.** Call `pytesseract.image_to_data` for word boxes and confidences, not only `image_to_string`. Try the appropriate Tesseract layout modes (`--psm 3`, `4`, and `6`) on the candidate images, then select the result with the best confidence and valid-word coverage. Retain only sufficiently confident word tokens and reconstruct lines from their bounding boxes.
6. **Add a non-text rejection gate.** Reject or recapture when the page has too few confident words, too little alphabetic/dictionary-word coverage, implausible token lengths, sparse or non-line-like word boxes, or a low mean/median OCR confidence. Apply the test at word and page levels. This is the key defense against patterns that happen to resemble letters.
7. **Use multi-frame consensus for hard pages.** For pages that pass but remain near the acceptance boundary, OCR the two or three sharpest frames and keep words that agree spatially or textually. This reduces blur and transient glare without treating one noisy result as truth.
8. **Make failures observable and tune against evidence.** Save the original frame, detected page polygon, warped page, chosen preprocessing image, word-confidence overlay, and a compact JSON result during development. Report a clear reason such as `low_text_confidence`, `page_not_detected`, or `glare_or_blur` rather than writing a low-quality text file.

### Acceptance criteria

- A page is saved only when calibrated benchmark thresholds for confidence, valid-word coverage, and line layout all pass.
- All benchmark illustrations and decoration-only samples are rejected instead of saved as prose.
- Readable benchmark pages improve word error rate over the current one-pass baseline without unacceptable latency for a page flip.
- Debug artifacts make every accepted or rejected result explainable.

### Suggested implementation order

Start with phases 1, 5, and 6: they add measurements and a reliable rejection gate with the least camera-pipeline disruption. Then add multi-frame selection and page detection/rectification. Keep the current fixed crop behind a fallback switch until the contour detector has proven itself on the benchmark set.

### Implementation status

Implemented the first camera-pipeline slice in `backend/computer vision/book_ocr.py`:

- Multi-frame capture ranks frames by sharpness and exposure before OCR.
- A page-contour detector applies a perspective correction; the original fixed crop remains as a fallback.
- CLAHE/adaptive, illumination-corrected, and Otsu preprocessing candidates are evaluated across Tesseract page segmentation modes 3, 4, and 6.

### Eye-tracker controller

`backend/computer vision/read_mode_state.py` provides the state machine required by `eyetracking_opencv.py`. It starts in STOP mode, requires a three-second camera gaze to toggle READ/STOP, requires a look-away to rearm toggling, counts deliberate blinks within a two-second window, emits a directional flip after two blinks in READ mode, and returns to STOP after ten seconds of continuous eye closure. The controller is camera-independent and can be tested without MediaPipe or hardware.

MediaPipe `0.10.35` removed the legacy Python Solutions package needed by this eye tracker. The project now pins MediaPipe `0.10.14`, which provides the documented `mediapipe.solutions.face_mesh` iris-landmark API used by `eyetracking_opencv.py`; PySerial remains declared alongside the OCR dependencies.

The book OCR program accepts `--camera <index>` (for example, `python ".\\backend\\computer vision\\book_ocr.py" --camera 1`). It tries the Windows DirectShow backend first, reports the selected camera before opening it, and falls back to OpenCV's default backend. This makes camera selection explicit and reduces startup hangs on Windows.

### First live calibration

Two real camera captures were inspected through their saved diagnostics. One contained 33 confident words at 83.45% mean confidence across eight lines, but was rejected only because its text-like-token ratio was 62.3%, narrowly below the original 65% threshold. A separate noisy capture had only a 13.2% ratio and remains a clear rejection. `MIN_TEXT_LIKE_RATIO` is now 60%, while the independent confidence, word-count, and line-layout gates remain in place.

A later rejected capture correctly showed a face and whiteboard rather than a book page. The operator must use the preview window to confirm that the page fills the camera view before pressing `c`; do not lower the non-text gate to accept that case. The successful book capture was a little soft and included an illustration at the page edge, so stable focus, even lighting, and a page-centered camera mount remain important for the next calibration pass.

### Optional OpenAI vision pipeline

`book_ocr.py` now supports `--openai-review`. Local OpenCV/Tesseract first selects the strongest page candidate, then an opt-in OpenAI Responses API call reviews only that perspective-corrected page image. The reviewer receives the local draft as untrusted context and must return JSON that either transcribes readable printed book prose or rejects the image. A valid vision transcription replaces local OCR; an API failure or rejection leaves the local result rejected. The image request uses `store=False`, requires `OPENAI_API_KEY` plus `OPENAI_OCR_MODEL`, `OPENAI_MODEL`, or `--openai-model`, and writes its outcome to each metrics JSON file.

The existing `backend/.env` uses `OPENAI_MODEL` rather than `OPENAI_OCR_MODEL`. The OCR command now falls back to that existing model variable, avoiding duplicated configuration; `OPENAI_OCR_MODEL` remains available when OCR should use a different vision-capable model.
